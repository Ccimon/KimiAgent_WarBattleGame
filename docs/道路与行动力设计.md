# 道路与行动力机制设计

> 状态:已全部实施(2026-08-07)。第 1 步(道路)、第 2 步(行动力)均通过构建 + 无头模拟验证(AP 不变量、道路不变量、三行为在约束下正常运转)。
> 相关代码:`src/game.ts`、`src/levels.ts`、`src/render.ts`、`src/main.ts`

## 背景

当前模型:任意两塔直线可达(全连接图)、塔可无限频率出兵(只受"蓄力门槛"软限制)。引入两个机制增加战术深度:

1. **道路**:塔之间按边连接,只能沿边派兵,产生前线/后方、咽喉要道。
2. **行动力(AP)**:出兵消耗 AP,AP 随时间回复,不足则不能出兵,出兵频率成为资源决策。

## 第 1 步:道路机制(已定稿)

### 数据与规则

- `LevelDef` 增加 `edges: [number, number][]`(塔下标对,无向)。6 个关卡全部手工标边。
- `sendUnits` 增加邻接校验:两塔间无边则返回 `false`。
- 队伍沿边直线行军(边即直线段),行军时间 = 边长 / `SQUAD_SPEED`,现有逻辑不变。
- 不做多跳规划:玩家和 AI 都只能以邻接塔为目标;要去远处需先占领/支援中间塔。

### 玩家交互

- 渲染层先画道路(塔之间连线),再画队伍和塔。
- 拖拽中仅**邻接塔**高亮为合法目标;松手落在非邻接塔上无动作(不发指令)。
- 联机客人端同样按 levelIndex 从 `LEVELS` 拿到边表,无需进快照;房主端负责最终校验(防篡改)。

### AI 适配

三种行为的候选目标全部加邻接过滤:

- **支援**:受威胁塔只向"邻接 + 安全 + 富裕(≥ SUPPORT_RICH)"的己方塔求援;"援军到不了就放弃"的判断沿用(距离即边长)。
- **扩张**:只抢邻接灰塔,评分与去重规则不变。
- **进攻**:只打邻接敌塔;猎强在邻接敌塔中挑"所属势力总兵力最强"的,没有邻接强敌时退化为打最弱邻接敌塔。
- 无邻接目标时对应行为自然空转(如被围死就等死/憋兵),不做跨图规划。

## 第 2 步:行动力机制(已定稿,待实施)

### 规则与数值(初版,试玩后调)

- `Tower` 增加 `ap` 字段;常量:`AP_MAX = 100`、`SEND_COST = 34`(满 AP 约可连续出兵 3 次)、`AP_REGEN = 8`(每秒回复,约 4.25 秒回够一次)。
- 固定扣费:每次成功出兵扣 `SEND_COST`,与派出兵力、距离无关;`ap < SEND_COST` 时 `sendUnits` 返回 `false`。
- AP 回复与产兵循环并列(中立塔也回 AP,无害且简化逻辑);增援接收不耗 AP,只有主动出兵耗。

### 玩家交互与联机

- 渲染:塔下方画 AP 小条(或数字),拖拽预览时 AP 不足给视觉提示(如预览线变灰)。
- 快照 `towers` 增加 `ap` 字段(每塔多一个数,协议小改);客人端显示与手感跟随快照。
- 客人端发指令前本地预判 AP,不足不发(房主端仍做最终校验)。

### AI 适配

- 三种行为的出兵条件统一追加 `ap >= SEND_COST`(在 `sendUnits` 校验即可,AI 无需特判——出兵失败自动等下一 tick)。
- 性格差异自然显现:莽夫 AP 全砸进攻,被围时无 AP 回防;龟缩省 AP 给支援。不为 AP 加新的性格参数(先观察)。

## 不做的事(控制范围)

- 不做多跳自动寻路/接力派兵(玩家与 AI 都只走邻接边)。
- 不做有向边、道路通行费等变体。
- AP 不做按兵力/距离扣费的变体(初版固定扣)。
- 旧关卡的数值不重新平衡,先试玩再调。

## 验证

- 每步完成后:`npm run build` + 无头模拟(道路:确认无跨边出兵、AI 三行为在图约束下仍运转;AP:确认出兵频率受限)+ 手动试玩。
